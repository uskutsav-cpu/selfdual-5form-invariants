## Why these two runs and not a fresh matrix

a single finite-difference Jacobian over these 83 candidates takes more than ten minutes even with parallel evaluation, so a full seed x scale x step matrix was not run here. The archived matrices are the data those runs actually produced and are analysed directly.

## Classification rule

A run is **nondegenerate** only when every scheduled candidate row is
meaningfully non-zero, the rank does not depend on an isolated
tolerance, and the singular spectrum has a documented gap. A row at or
below the declared noise floor (relative `1e-12`)
is never normalised.

> rows at or below the noise floor are never normalised

## Reading the table

The two runs are the same code at different random points. In `tensor-words run` no row sits at the noise floor, the rank is the same across the whole tolerance sweep, and the spectrum has a gap of `2.04e+07` at index 81. Row normalisation is legitimate there and the run supports rank 81.

In `full-dense-safe run`, 48 of the scheduled rows evaluate to numerical zero. Their surviving entries are rounding noise. The gap at index 81 is `1.27` -- that is, there is no gap -- so no tolerance choice is defensible, and the honest rank is 35. Normalising the near-zero rows rescales noise to unit length and reports 83, which is fabricated.

Both are kept. The degenerate run is the evidence that a genericity
check is not optional, and deleting it would remove the reason the
rule exists.

## What replaced this computation

The floating-point Jacobian is superseded by an exact analytic one.
No step size, no rank tolerance, no row normalisation, and no
classification rule is needed, because over `F_p` zero means zero.

    scheduled 83, evaluated 83, errors 0, zero rows 0
    exact modular rank 81 at 2 sample point(s)
    characteristic-zero lower bound 81, unconditional

The float64 runs are retained as evidence about the *method*, not as
support for the rank. See `docs/RANK81_EXACT_CERTIFICATE.md`.
